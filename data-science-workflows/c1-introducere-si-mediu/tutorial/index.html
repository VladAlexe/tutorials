Cursul 1 · Manual

Introducere și configurare

Conținutul lecției, explicat pe larg, cu aceleași exerciții. Exercițiile pornesc de la zero la fiecare deschidere a paginii; răspunsurile date la curs și acasă se înregistrează în contul personal.

01 · Cursul

Fluxuri de lucru pentru știința datelor

Cursul urmărește drumul complet al unui proiect de analiză de date, de la formularea întrebării până la un raport pe care alți cercetători îl pot citi, reproduce și evalua. Nu este un curs de statistică și nici unul de programare: tema lui este felul în care cele două se leagă într-un proces de lucru reproductibil, care funcționează în echipă, nu doar pe un singur calculator.

Materia are unsprezece subiecte, distribuite pe opt ședințe. Fiecare ședință adaugă o componentă la proiectul echipei, iar la final proiectul se predă ca depozit de cod pe GitHub, cu istoricul lui, nu ca fișier izolat. Pe site, ședințele sunt numerotate „cursul 1” până la „cursul 8”; fiecare are o parte de curs, cu lecția și manualul de pe site, și un laborator, cu caietul ei.

Pe parcursul semestrului, cursul urmărește aceeași întrebare de cercetare, ca într-un proiect real: cât de conectate sunt regiunile Europei prin prieteniile de pe Facebook și în ce măsură aceste legături se explică prin migrația dintre ele. Fiecare echipă dezvoltă, pe aceleași date, o întrebare proprie.

Caiete și fișiere de cod

Caietul (.ipynb) este potrivit pentru explorare: se rulează o celulă, se examinează rezultatul, se decide pasul următor. Fișierul .py este potrivit pentru ce se rulează din nou, identic, de fiecare dată: descărcarea datelor, curățarea, construirea tabelului final. Un proiect de date folosește ambele forme, iar VS Code le deschide în același mediu de lucru.

De ce un mediu virtual

Fiecare proiect are pachetele lui, în versiunile lui. Mediul virtual le izolează de restul calculatorului, astfel încât proiectul echipei să ruleze cu aceleași pachete pe toate cele cinci calculatoare. Când versiunile sunt fixate în requirements.txt (de exemplu pandas==3.1.0), mediul se poate reface identic și peste un an.

Contul GitHub

Se creează înainte de prima oră, după pașii de pe pagina cursului. La prima oră, contul servește la autentificarea pe site, iar numele se alege o singură dată din lista grupei. De la cursul 2, același cont dă acces la depozitul echipei.

Ce date se salvează

Răspunsurile la întrebări, exercițiile rezolvate și prezența la orele de curs. Detaliile sunt în politica de confidențialitate.

05 · Pașii unui proiect

Pașii unui proiect de analiză de date

Schema are trei benzi. Prima, analiza datelor, acoperă etapele de sus, de la definirea problemei până la analiza exploratorie. A doua, ML engineering, acoperă implementarea și optimizarea modelului. A treia, știința datelor, le cuprinde pe toate, împreună cu construirea variabilelor, modelarea și baza de date care leagă etapele. Raportarea încheie drumul: un rezultat devine util abia când poate fi citit și verificat de altcineva.

ExplorareData Science Workflow

Săgețile punctate marchează revenirile și descriu cel mai bine felul real de lucru. Dacă la curățare reiese că un indicator lipsește pentru jumătate dintre unități, se revine la colectare; dacă analiza exploratorie arată o relație neașteptată, se revine la definirea problemei. Revenirile nu sunt abateri de la metodă, ci fac parte din ea.

07 · Proiectul

Social Connectedness Index

Indicele este produs de Data for Good at Meta din rețeaua de prietenii Facebook, agregată și anonimizată. Pentru fiecare pereche de locuri, el exprimă cât de probabil este ca doi utilizatori Facebook, câte unul din fiecare loc, să fie prieteni, relativ la celelalte perechi. Valorile sunt scalate: în fișier, cea mai mare este exact 1.000.000.000, iar cea mai mică 1. SCI nu este, așadar, o probabilitate între 0 și 1 și nu se interpretează izolat, ci prin comparație între perechi.

Definiția (Johnston et al., 2026): SCIi,j = Prieteniii,j / (Utilizatorii × Utilizatorij), adică numărul de prietenii Facebook dintre utilizatorii din locurile i și j, împărțit la produsul numerelor de utilizatori Facebook din fiecare loc. Fiecare prietenie are aceeași pondere. Rezultatul se rescalează apoi, separat pentru fiecare fișier, între 1 și 1.000.000.000; statisticile publicate sunt protejate prin confidențialitate diferențială, adică printr-un zgomot statistic mic adăugat valorilor. Numitorul are două consecințe, relevante pe tot parcursul semestrului. Prima: un loc cu mulți utilizatori are nevoie de mult mai multe prietenii pentru același indice, deci o comunitate mare de migranți într-o țară mare are o pondere mică. A doua: indicele descrie utilizatorii platformei, nu populația, iar acoperirea Facebook diferă de la o țară la alta.

Pas cu pasAceleași calcule, două perechi de locuri

Ce nu este SCI

  • Nu este un număr de prietenii. Valorile nu se adună și nu li se calculează direct media între perechi.
  • Nu este mărimea diasporei. Clasamentul partenerilor după SCI diferă de clasamentul după numărul de migranți: Italia are cei mai mulți cetățeni români, dar este abia al șaselea partener al României după SCI.
  • Nu acoperă toată populația. Baza sunt utilizatorii Facebook activi în cele 30 de zile dinainte de 25 ianuarie 2026, cu peste 20 de prieteni; locurile cu mai puțin de 500 de utilizatori lipsesc (Johnston et al., 2026). Acoperirea diferă în funcție de vârstă, mediul de rezidență și țară.
  • Nu se compară între fișiere. Fiecare fișier este scalat separat, de la 1 la 1.000.000.000: valorile din fișierul pe țări și cele din fișierul pe regiuni nu sunt direct comparabile.
  • Nu are direcție. Prefixele user_ și friend_ din numele coloanelor marchează cele două capete ale perechii, nu o direcție a migrației: valoarea pentru România și Ungaria este aceeași în ambele sensuri.

Dintr-o valoare SCI se poate spune cât de conectați sunt, relativ, utilizatorii Facebook din două locuri. Nu se poate spune câți migranți trăiesc într-un loc sau de ce sunt legate locurile: pentru aceasta este nevoie de alte date, iar a doua sursă a cursului este migrația.

08 · Proiectul

Harta, pe județe

Harta arată unde duce analiza. Fiecare dintre cele 1.343 de regiuni NUTS 3 ale Europei (pentru România, județele) este colorată după cât de legată este de județul ales. Valoarea din listă este un raport: de câte ori este mai mare SCI-ul cu locul respectiv decât SCI-ul median al județului ales.

Hartă, date reale1.343 de regiuni NUTS 3 din toată Europa

Două regularități se văd imediat. Prima: aproape toate legăturile foarte puternice sunt cu regiuni apropiate, din aceeași țară; distanța și granița de stat organizează cea mai mare parte a hărții. A doua: fiecare județ are și câteva legături îndepărtate neobișnuit de puternice, diferite chiar între județe vecine. Pentru Suceava, Belgia (Turnhout); pentru Cluj, nord-estul Spaniei (Lleida și Huesca); pentru Dolj, nordul Germaniei și Huelva.

Aceste hărți seamănă cu hărțile migrației, dar nu sunt hărți ale migrației: SCI plasează utilizatorii după locul în care trăiesc, fără informații despre originea sau migrația lor. De aici întrebarea cursului: cât din aceste legături se explică prin oamenii care au migrat? Migrația este tema secțiunii următoare.

De unde vine harta

Din fișierul SCI pe regiuni NUTS 3, nuts3_2024.csv, publicat pe HDX, și din contururile NUTS 2024 de la Eurostat GISCO. Harta completă a Europei, pe toate nivelurile, este în Exploratorul legăturilor sociale.

Oameni și legături

A doua sursă a cursului este migrația: câți cetățeni ai fiecărei țări trăiesc în fiecare altă țară. Datele vin tot prin API, de la Eurostat (migr_pop1ctz), și se colectează la cursul 2. Sunt două hărți diferite, comutate din butoanele de sus: prima arată unde trăiesc cetățenii români, a doua cât de legată este România de fiecare țară, după SCI.

Datele de migrație disponibile

Stocul de cetățeni străini la 1 ianuarie 2024, pentru țările care raportează populația pe țări de cetățenie. Printre cele care nu raportează: Polonia, Danemarca, Grecia, Croația, Cipru, Malta, Elveția, Regatul Unit și cele mai multe țări din afara UE (Republica Moldova, Ucraina, Serbia). Pe ce loc este Italia printre partenerii României, după SCI?

Al șaselea, după Republica Moldova, Austria, Germania, Ungaria și Irlanda. La migrație este prima. Diferența dintre cele două clasamente este chiar întrebarea proiectului.

10 · Proiectul

SCI urmează proporția românilor, nu numărul lor

Întrebarea este ce explică mai bine SCI cu România: numărul de români care trăiesc într-o țară sau proporția lor în populația acelei țări. Franța și Austria o lămuresc pe un singur exemplu. Au aproape același număr de români (161.220 și 153.427), dar Franța are 68,7 milioane de locuitori, iar Austria 9,2 milioane: în Franța trăiește un român la 426 de locuitori, în Austria unul la 60. SCI-ul cu România este de 6,9 ori mai mare în Austria, aproape cât raportul proporțiilor (7,1).

Explicația vine din formula indicelui: prieteniile dintre cele două locuri se împart la produsul numerelor de utilizatori. Dacă românii din Franța și cei din Austria au, împreună, cam tot atâtea prietenii cu România, în Franța ele se împart la utilizatorii unei țări cu de 7,5 ori mai mulți locuitori, deci indicele iese de câteva ori mai mic.

un locuitor un român

Aceeași comparație, pe toate cele 23 de țări care raportează cetățeniile. În stânga, SCI cu România față de numărul de români; în dreapta, față de românii la 1.000 de locuitori. Fiecare punct este o țară, iar ambele axe sunt logaritmice, pentru că valorile acoperă câteva ordine de mărime.

Date realeSCI și migrația, în 23 de țări

Pe valorile logaritmate, în cele 23 de țări care raportează cetățeniile, corelația cu SCI este 0,78 pentru numărul de români și 0,87 pentru românii la mie. Aceeași relație revine în modelul de la cursul 7, unde rata la mie explică mult mai mult decât numărul absolut. Explicația ține de numitorul indicelui: SCI împarte la utilizatorii din ambele locuri, deci o comunitate mare într-o țară mare are o pondere mică. Țările care rămân în afara tiparului, ca Ungaria, sunt întrebări de proiect.

Virgula zecimală

Într-un fișier românesc, zecimalele se scriu cu virgulă: 3,7. float("3,7") produce o excepție ValueError, iar aici eroarea este un avantaj. Problema apare la citirea unui fișier întreg: coloana rămâne text, se sortează lexicografic și nu semnalează nimic. Corecția este float(x.replace(",", ".")) pentru o valoare, sau decimal="," în pd.read_csv, pentru tot fișierul.

Lipsă, zero, text gol

None, 0 și "" sunt trei lucruri diferite. Zero este o valoare măsurată; None înseamnă că valoarea lipsește. În caiet, Ana are ocupația None: ocupația ei este necunoscută. Mihai are 0.0 ore de studiu: studiază zero ore. Dacă valorile lipsă sunt tratate ca zerouri, media scade fără nicio eroare.

Tipuri de date în SQL

De la cursul 5, datele proiectului stau într-o bază de date, nu în fișiere. Acolo tipurile nu se deduc la citire, ci se declară la crearea tabelului, iar baza de date respinge valorile care nu se potrivesc (așa procedează PostgreSQL, baza de date a cursului). Regimul este mai strict decât în Python, cu un avantaj: o greșeală de tip apare la inserare, nu mai târziu, în analiză.

FamilieTipuriPentru ce
NumericeINT, BIGINT, NUMERIC, DOUBLE PRECISIONValori întregi (frecvențe, ani), valori calculate
Dată și timpDATE, TIME, TIMESTAMPMomente în timp; nu se păstrează ca text
CaractereCHAR, VARCHAR, TEXTNume, coduri, descrieri

CHAR, VARCHAR sau TEXT

  • CHAR(n) are lungime fixă și completează cu spații valorile mai scurte. Potrivit pentru coduri de lungime constantă, ca codurile de țară din două litere.
  • VARCHAR(n) are lungime variabilă, cu o limită maximă.
  • TEXT nu are o limită declarată. În PostgreSQL nu este mai lent decât VARCHAR, de aceea este alegerea implicită pentru text liber.

Documentația PostgreSQL notează că CHAR(n) nu aduce un câștig de performanță față de celelalte două; aici este folosit pentru că exprimă explicit regula „exact două caractere”. VARCHAR(2) ar fi o alegere la fel de corectă.

Cât spațiu ocupă un număr întreg

SMALLINT2 octeți · până la 32.767
INT4 octeți · până la 2.147.483.647
BIGINT8 octeți · până la 9.223.372.036.854.775.807

Fiecare valoare din coloană ocupă atâția octeți, pe fiecare rând. Se alege cel mai mic tip în care încape cea mai mare valoare posibilă, nu cea mai mare valoare observată. La cele 1,8 milioane de rânduri din fișierul pe regiuni NUTS 3, diferența dintre INT și BIGINT este de 7,2 MB, doar pentru o coloană. Detaliile: tipurile numerice în PostgreSQL.

Activarea

După activare, pip și python din terminal sunt cele din .venv, iar linia din terminal începe cu (.venv). Fără activare, pip install pune pachetele în Python-ul comun al calculatorului, iar caietul nu le găsește în mediu.

Pe Windows, PowerShell poate refuza scriptul de activare, cu o eroare despre execution policy. Soluția: comanda de mai jos, rulată o singură dată, apoi o nouă activare.

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

Funcționează și fără activare, cu interpretorul mediului apelat prin calea completă: .venv\Scripts\python -m pip install -r requirements.txt pe Windows, .venv/bin/python -m pip install -r requirements.txt pe macOS. VS Code activează oricum automat mediul în terminalele noi, după ce acesta a fost ales ca interpretor.

De ce .venv nu este în arhivă

Este mare, este construit pentru un anumit calculator și se reface din două comenzi. În arhivă se află doar lista pachetelor, requirements.txt, din care fiecare își construiește propriul .venv, cu aceleași pachete. La fel se procedează și în depozitul echipei.

Cum se verifică mediul activ

Prima celulă de cod din caiet afișează sys.executable, adică interpretorul Python care rulează caietul. Calea afișată trebuie să conțină .venv. Dacă un import nu funcționează, primul lucru de verificat este kernelul ales în dreapta sus.

import sys
print(sys.executable)   # calea trebuie să conțină .venv

Cum rulează un caiet

Un caiet are două feluri de celule: Markdown, cu text, și Code, cu Python. Variabilele create într-o celulă rămân în memoria kernelului, procesul Python din spatele caietului, de aceea celulele se rulează de sus în jos. Un NameError înseamnă, de obicei, că a fost sărită celula care definea variabila. Restart golește memoria kernelului, iar Run All rulează toate celulele în ordine; un caiet corect rulează fără erori după Restart urmat de Run All. Tastele de lucru sunt pe pagina Comenzile rapide din Jupyter.
