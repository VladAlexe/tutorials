Lecția 3 din 8

Versionare și colaborare cu Git

La lecția anterioară au fost colectate date. Această lecție asigură că datele și codul care le-a colectat nu se pierd: Git, GitHub, lucrul în echipă și întrebarea de cercetare a proiectului.

Lecția se deschide după ce este predată la curs. Până atunci, descrierea de mai jos rămâne disponibilă.

Despre lecție

Ora are două părți, aparent fără legătură. Prima tratează Git, adică modul în care un proiect își păstrează istoricul: cele trei zone între care se mută fișierele, apoi depozitul echipei, de la GitHub pe calculator: clonarea, ce nu intră în depozit, primul commit pe main, ramura dev pe care lucrează toată echipa, regula pull înainte de push, conflictele și verificarea.

A doua construiește cadrul proiectului: legătura dintre două locuri, măsurată prin SCI, și factorii care o pot explica (distanța, migrația, istoria comună, locurile), fiecare cu ipoteza, variabila și sursa lui. Din ce rămâne neexplicat pornește întrebarea echipei. Lecția se încheie cu tabelele pregătite în caietul 03.

Legătura dintre ele: un proiect de analiză nu este o colecție de fișiere, ci un parcurs. Git păstrează parcursul, iar cadrul teoretic îi stabilește direcția. Fără primul, drumul până la rezultat nu poate fi reconstituit; fără al doilea, punctul de plecare nu poate fi justificat.

Obiectivele lecției

  • Diferența dintre Git și GitHub și motivul pentru care un commit local nu este o copie de siguranță a muncii.
  • Fiecare comandă, explicată prin zonele între care mută fișierele.
  • Depozitul echipei, clonat de pe GitHub, și rolul fiecărui dosar din șablon.
  • Ce intră în depozit (caiete, cod, date mici) și ce rămâne în afara lui, prin .gitignore: secretele, mediul virtual, fișierele uriașe.
  • Primul commit al echipei, pe main, și fluxul de după: dev pentru lucrul zilnic, pull înainte de push, rezolvarea unui conflict.
  • Citirea ieșirii lui git status și verificarea depozitului, local și pe GitHub.
  • Structura unui cadru teoretic: factor, ipoteză, variabilă, sursă.
  • O întrebare de cercetare care poate fi infirmată cu datele disponibile.

Pregătire

Lecția poate fi urmărită fără programe instalate. Partea practică necesită ce a fost pregătit la cursul 2:

  1. Git, instalat. Pe Windows include Git Bash, un terminal în care funcționează comenzile din lecție.
  2. Contul de GitHub, același cu care se face intrarea pe site.
  3. Echipa, aleasă pe site. Datele colectate în C2 sunt și în depozitul cursului, iar caietul 03 le citește de acolo, ca toată lumea să lucreze pe aceleași date. Repo-ul echipei, echipa-N, există deja pe GitHub; invitația vine doar dacă numele de pe site este legat de contul GitHub (Contul meu → „Caută-mi numele”). Clonarea în dsw/proiect se face în această lecție.
