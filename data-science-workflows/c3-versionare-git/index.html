Lecția 3 din 8

Versionare și colaborare cu Git

Datele colectate în C2 devin, în această lecție, baza unui proiect de echipă: sursele sunt aduse la o structură comună, codul și datele intră sub controlul versiunilor, iar echipa își formulează întrebarea de cercetare.

Lecția se deschide după ce este predată la curs. Până atunci, descrierea de mai jos rămâne disponibilă.

Despre lecție

Lecția acoperă trei componente ale aceluiași flux de lucru.

Preprocesarea. În caietul 03, funcțiile de colectare din C2 trec într-un modul, src/date_api.py, iar sursele noi (nomenclatorul NUTS de la GISCO, SCI pe regiuni NUTS 2, șapte indicatori regionali Eurostat, zborurile dintre țări) sunt aduse la o structură comună: coloanele necesare, denumiri consecvente, unitatea de analiză corectă. Rezultatul sunt cinci tabele în data/processed, pregătite pentru curățarea și integrarea din C4.

Versionarea. Git înregistrează istoricul proiectului, iar GitHub îl pune la dispoziția echipei. Lecția pornește de la modelul celor trei zone, apoi urmează depozitul echipei: clonarea, conținutul lui .gitignore, primul commit pe main, ramura dev, regula pull înainte de push, rezolvarea conflictelor și verificarea depozitului.

Cadrul teoretic. Legătura dintre două locuri, măsurată prin SCI, este pusă în relație cu factorii care o pot explica (distanța, migrația, istoria comună, caracteristicile locurilor), fiecare cu ipoteza, variabila și sursa sa. Variația rămasă neexplicată este punctul de plecare al întrebării fiecărei echipe.

Cele trei componente corespund unor cerințe distincte ale reproductibilității: istoricul versiunilor permite reconstituirea drumului de la date la rezultat, preprocesarea documentată face transformările verificabile, iar cadrul teoretic justifică alegerea variabilelor.

Obiectivele lecției

  • Cele patru operații ale preprocesării (selecția coloanelor, redenumirea, restrângerea la unitatea de analiză, concatenarea) și diferența dintre preprocesare și curățare.
  • Organizarea codului reutilizabil într-un modul .py și importul lui din caiete.
  • Diferența dintre Git și GitHub și motivul pentru care un commit local nu este o copie de siguranță.
  • Comenzile Git, explicate prin zonele între care mută modificările.
  • Structura depozitului echipei și ce intră în el, respectiv ce rămâne în afara lui prin .gitignore.
  • Lucrul în echipă: main și dev, pull înainte de push, rezolvarea unui conflict.
  • Citirea ieșirii lui git status și verificarea depozitului, local și pe GitHub.
  • Structura unui cadru teoretic (factor, ipoteză, variabilă, sursă) și o întrebare de cercetare care poate fi infirmată cu datele disponibile.

Pregătire

Partea practică presupune:

  1. Git, instalat. Pe Windows, instalarea include Git Bash; comenzile lecției funcționează și în PowerShell, în terminalul din VS Code.
  2. Contul de GitHub cu care se face autentificarea pe site.
  3. Echipa aleasă pe site. Depozitul ei, echipa-N, există deja pe GitHub; invitația se trimite doar membrilor care și-au legat numele de pe site de contul GitHub (Contul meu → „Caută-mi numele”).
  4. Caietul 03, descărcat în dsw/curs/. Datele colectate în C2 se citesc din depozitul cursului, astfel încât toți participanții lucrează pe aceleași fișiere.
