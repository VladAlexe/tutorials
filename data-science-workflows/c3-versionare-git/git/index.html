git config --global user.nameverificarea numelui

git init în dosarul greșit

Se șterge doar depozitul local, din PowerShell, în dosarul respectiv: Remove-Item -Recurse -Force .git. Fișierele rămân neatinse.

Depozitul echipei: git clone

Varianta folosită la curs și în proiecte: depozitul există deja pe GitHub, în organizația dsw-ubb-2026. Comenzile se dau din dosarul dsw.

git clone https://github.com/dsw-ubb-2026/<depozitul-echipei>.git proiectcopiază depozitul, cu tot istoricul, în dosarul proiect
cd proiectintră în depozit
git statusce vede Git
git branch -vvarată că main urmărește origin/main

Fără depozit pe GitHub: git init

Doar dacă depozitul nu există încă pe GitHub. Depozitul de pe GitHub se creează gol, fără README.

git initcreează depozitul local, gol
git add .adaugă fișierele existente
git commit -m "first commit"primul commit
git branch -m master mainramura principală se numește main
git remote add origin <adresa>leagă depozitul local de cel de pe GitHub
git push -u origin maintrimite main pe GitHub și reține legătura

Caz special: depozitul de pe GitHub există deja și are conținut

git initdepozitul local
git branch -m master mainramura principală se numește main
git remote add origin <adresa>legătura cu GitHub
git pull origin main --allow-unrelated-historiesunește cele două istorii, o singură dată
git branch -u origin/mainleagă main local de origin/main

.gitignore

Un fișier text în rădăcina proiectului, cu ce nu intră în Git: mediul virtual, secretele, datele (se refac rulând caietele) și fișierele uneltelor. Se scrie înainte de primul git add.

.venv/
venv/
.env
data/
*.csv
*.parquet
*.xlsx
.ipynb_checkpoints/
__pycache__/
*.pyc
.vscode/
.DS_Store
Thumbs.db
git add .gitignoreși el este un fișier al proiectului
git commit -m "add gitignore"
git push
git statusfișierele ignorate nu mai apar

Un fișier adăugat din greșeală

git reset -- "Nume fisier cu spatii.ipynb"îl scoate din pregătire; fișierul rămâne pe disc
git rm --cached nume_fisierGit nu îl mai urmărește, dar fișierul rămâne în proiect

Comenzile de bază

Tot ce s-a schimbat, fără ce este în .gitignore

git add .toate fișierele noi și modificate intră în pregătire
git commit -m "mesaj scurt, clar"commit-ul, cu un mesaj care spune ce s-a schimbat
git pushtrimite commit-ul pe GitHub

Un singur fișier

git add nume_fisierdoar acest fișier intră în pregătire
git commit -m "mesaj"
git push

Modificările colegilor

git pulladuce de pe GitHub modificările ramurii curente; se folosește când git status este curat, altfel apar îmbinări și commit-uri suplimentare

Ramurile

git branchramurile locale; cea curentă este marcată
git branch -rramurile de pe GitHub (origin/…)
git branch -atoate ramurile, locale și de pe GitHub
git branch -vfiecare ramură, cu ultimul commit
git branch -vvfiecare ramură, cu upstream-ul ei (de exemplu [origin/main])

Upstream este legătura dintre ramura locală și cea de pe GitHub, folosită de git pull și git push.

Ramura dev

O creează un singur membru, o singură dată

git switch -c devcreează dev pornind din main și trece pe ea
git push -u origin devcreează dev pe GitHub și reține legătura

Restul echipei

git fetchaduce informațiile noi despre ramurile de pe GitHub
git switch devtrece pe dev
git branch -averificarea: apare și remotes/origin/dev

Lucrul zilnic pe dev

La începutul lucrului

git switch dev
git pullultima versiune a ramurii dev

Lucrul se face, pe cât posibil, în fișiere separate, de exemplu analiza_vlad.ipynb și analiza_maria.ipynb.

La salvarea muncii

git statusce s-a schimbat
git add .
git commit -m "ce s-a făcut"
git pullîn caz că un coleg a trimis ceva între timp
git push

Conflict la git pull

Se rezolvă local, în fișier (se păstrează varianta corectă și se șterg marcajele), apoi:

git add .
git commit -m "rezolvat conflict"
git push

dev în main

Nu doar la finalul proiectului și nici după fiecare commit, ci după fiecare sarcină importantă încheiată: curățarea datelor, setul de vizualizări, modelul final.

git switch main
git pullmain local, la zi cu origin/main
git merge devaduce în main commit-urile din dev
git pushtrimite main pe GitHub

git merge dev ia toate commit-urile care există în dev, dar nu și în main, și le aplică peste main. După îmbinare, main conține tot ce s-a făcut și s-a verificat în dev.

Regulile echipei

Mai ales cu caiete Jupyter, care nu se îmbină ușor:

  1. Toată echipa lucrează pe dev, nu pe main.
  2. Fiecare lucrează, pe cât posibil, în fișiere separate (caiete diferite).
  3. git pull la începutul lucrului și înainte de fiecare push.
  4. dev intră în main doar când sarcina este curată: verificată, fără fișiere de test.
  5. main rămâne o versiune stabilă, schimbată doar prin îmbinări deliberate din dev.
