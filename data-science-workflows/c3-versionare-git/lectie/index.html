Ce face Git

Git rulează pe calculatorul local. GitHub este doar platforma pe care se sincronizează proiectele.

  1. 01
    Înregistrează fiecare schimbareistoric

    Nu doar ultima versiune, ci toate, cu autorul și data fiecărei schimbări.

  2. 02
    Permite revenireareveniri

    La orice versiune anterioară, fără pierderea stării curente.

  3. 03
    Permite lucrul în paralelcolaborare

    Mai multe persoane lucrează pe aceleași fișiere, iar Git îmbină apoi modificările.

  4. 04
    Păstrează totul în dosarul proiectuluiun singur loc

    Întreaga istorie se află în subdosarul .git, nu într-un serviciu extern.

  5. 05
    Izolează experimenteleramuri

    Modificările experimentale se fac pe o ramură separată, iar codul principal rămâne neatins.

  6. 06
    Funcționează localfără internet

    Git nu necesită conexiune la internet. GitHub este doar locul de sincronizare.

Git și GitHub

Două unelte diferite: una ține istoricul, cealaltă îl pune în comun.

Gitprogram instalat pe calculator
  • păstrează istoricul proiectului
  • funcționează fără internet
  • se folosește din terminal
GitHubplatformă online
  • găzduiește depozitele, ca o copie independentă de calculator
  • spațiul comun al echipei, fără arhive trimise prin email
  • arată cine ce a făcut și când
Evaluarea proiectului

Proiectul se evaluează pe baza depozitului: întregul parcurs, nu doar rezultatul final. Un singur commit în ziua predării nu documentează acest parcurs.

ExercițiuCe intră în depozit

Un fișier cu o parolă a fost inclus din greșeală într-un commit și trimis cu push. Ce trebuie făcut?

Prima măsură este schimbarea parolei. Celelalte variante lasă parola în istoric, de unde poate fi extrasă imediat de oricine știe unde să caute. Curățarea istoricului urmează și este mai dificilă: cere rescrierea istoricului, iar copiile deja descărcate rămân.

Când două persoane modifică aceleași rânduri

La git pull, Git nu poate alege între variante: le inserează pe amândouă în fișier, iar alegerea se face manual. După rezolvare: git add ., git commit -m "rezolvat conflict", git push.

ExercițiuRezolvarea conflictului

Cinci reguli pentru acest semestru

1Fiecare în fișierul luiun caiet pe pas, cu un autor; două persoane în același caiet înseamnă conflict
2git pull întâila începutul lucrului și înainte de fiecare push
3main rămâne stabillucrul zilnic, pe dev; în main intră doar pași încheiați
4Mesaje descriptivece s-a schimbat, nu „update”
5Fără secrete, fără fișiere uriașeparolele nu intră deloc; peste 50 MB, doar adresa de unde se descarcă
Toate comenzile, pe o pagină
