Colectarea datelor prin API

La cursul 1, datele au venit dintr-un fișier descărcat dinainte. Pentru o analiză care trebuie refăcută, verificată și actualizată, drumul de la sursă la tabel trebuie să fie el însuși reproductibil: cine citește rezultatul trebuie să poată afla de unde vine fiecare valoare, cu ce filtre a fost cerută și când.

Un API (application programming interface, interfață de programare a aplicațiilor) face drumul acesta explicit. Datele vin printr-o cerere scrisă, care conține sursa, setul și filtrele, și care se poate rula din nou, de altcineva, cu același rezultat sau cu o diferență care se poate explica.

03 · Ce este un API

Ce este un API

Analogia restaurantului fixează un principiu esențial: codul clientului nu comunică direct cu baza de date a furnizorului. Comunică cu un intermediar, care o accesează în numele clientului, în condiții stabilite dinainte. Condițiile acestea sunt contractul API-ului, iar documentația e forma lui citibilă.

DiagramăAcelași drum, pe două straturi
La restaurantLa un API
masa, clientulscriptul
meniuldocumentația: ce resurse există, ce parametri primesc, ce formă are răspunsul
bonulcererea: metoda, adresa, parametrii
ospătarulAPI-ul, singura intrare spre date
bucătăria și cămaraserverul și baza de date
farfuriarăspunsul: un cod de stare și corpul

Patru proprietăți, nu doar un drum

Contractul. Documentația descrie complet ce se poate cere. Multe API-uri publică o descriere citibilă de mașini, în formatul OpenAPI, din care se generează documentație și cod.

Abstractizarea. Clientul depinde de contract, nu de implementare. Furnizorul își poate schimba serverele și baza de date fără ca scriptul clientului să se schimbe.

Versionarea. Când contractul se schimbă, furnizorul publică o versiune nouă (la Banca Mondială, /v2 din adresă), iar versiunea veche rămâne în funcțiune până la o dată anunțată.

Lipsa stării. Serverul nu păstrează nimic de la o cerere la alta. Fiecare cerere conține tot ce trebuie, deci o colectare întreruptă se reia de la pagina la care a rămas.

Limitele analogiei

Un API nu negociază și nu interpretează. O cerere care nu respectă contractul nu primește o explicație, ci un cod de eroare și, uneori, un mesaj scurt. De aceea documentația se citește înainte de prima cerere, nu după primul eșec.

Banca Mondială își mută datele pe alt server și schimbă baza de date, dar păstrează adresele și parametrii din documentație. Ce se întâmplă cu scriptul tău de colectare?

Scriptul depinde de contract (adrese, parametri, formatul răspunsului), nu de felul în care e construit serverul. Documentația, nu infrastructura furnizorului, e ce trebuie urmărit.

04 · Ce este un API

De ce colectăm prin API

Întrebarea apare firesc: dacă fișierul se poate descărca dintr-un clic, de ce ar fi nevoie de cod pentru a-l obține? Motivele țin de știință, de inginerie și de calitatea datelor, iar fiecare are și un cost.

Știință

Proveniență
Cererea înregistrează sursa, setul, filtrele și data colectării: e documentația colectării.
Reproductibilitate
Altcineva rulează același cod și obține același tabel, sau vede exact ce s-a schimbat.
Principiile FAIR
Accesul printr-un protocol standard e una dintre condițiile datelor reutilizabile (Wilkinson et al., 2016).

Inginerie

Scară
Toate regiunile NUTS 3, pe ani și pe indicatori: mii de valori, într-o singură buclă.
Actualizare
Statisticile oficiale se revizuiesc; aceeași cerere, rulată din nou, aduce versiunea curentă.
Filtrare la sursă
Serverul trimite doar felia cerută, nu tot setul.
Automatizare
Colectarea se poate programa, repeta și verifica fără intervenție manuală.

Calitatea datelor

Integritate
Fără copieri și conversii manuale. Aproximativ o cincime din articolele cu liste de gene în anexe Excel aveau nume de gene transformate în date calendaristice (Ziemann et al., 2016).
Metadate
Unitățile, etichetele și indicatorii de stare (estimat, provizoriu, ruptură de serie) vin odată cu valoarea.
Acces legitim
API-ul e calea prevăzută de furnizor, cu condiții și limite scrise.
Ce costă

Dependență de furnizor (versiuni, întreruperi), limite de cereri, chei de acces, timpul de citit documentația. Un fișier publicat, datat și versionat, cum e SCI de pe HDX, rămâne o alegere corectă.

Știință

O analiză e credibilă în măsura în care drumul de la sursă la rezultat poate fi verificat. O cerere scrisă e documentația colectării: conține sursa, setul, filtrele și, dacă este salvată, momentul colectării. Principiile FAIR (Findable, Accessible, Interoperable, Reusable) cer ca datele să poată fi accesate printr-un protocol standard, deschis (Wilkinson et al., 2016).

Inginerie

Proiectul lucrează cu sute de regiuni, pe mai mulți ani și pe mai mulți indicatori. Statisticile oficiale se revizuiesc după publicare, așa că aceeași colectare trebuie să poată fi rulată din nou, iar diferențele să poată fi comparate. Filtrarea la sursă reduce volumul transferat la felia de care e nevoie.

Calitatea datelor

Fiecare pas manual poate introduce erori sistematice. Exemplul cel mai citat vine din genetică: aproximativ o cincime din articolele cu liste de gene în anexe Excel conțineau nume de gene convertite automat în date calendaristice (Ziemann, Eren și El-Osta, 2016). Un răspuns structurat păstrează și metadatele: unități, etichete, indicatori de stare, pe care un export manual îi poate pierde.

Ce costă

Un API creează o dependență de furnizor: versiunile se schimbă, serviciile au întreruperi, iar limitele de cereri și cheile de acces trebuie gestionate. Un fișier publicat, datat și versionat rămâne o alegere corectă: SCI-ul din cursul 1 vine de pe HDX tocmai ca un instantaneu de felul acesta.

În practică, proveniența se păstrează simplu: data colectării în numele fișierului salvat, iar în caiet, celula care l-a produs.

06 · Tipuri de API

Trei decenii de API-uri

Istoria API-urilor nu e o succesiune în care fiecare tehnologie o înlocuiește pe cea dinainte. Sunt mai multe familii care au evoluat în paralel: apelurile la distanță, resursele și interogările, contractele și evenimentele, standardele statistice și, recent, protocoalele pentru agenți AI. Dedesubt, protocolul HTTP s-a schimbat și el, de la HTTP/1.0 la HTTP/3, fără să schimbe înțelesul unei cereri.

CronologieCinci familii, pe aceeași axă

REST e descris în 2000, în teza de doctorat a lui Roy Fielding, ca stil arhitectural al webului. Banda statisticilor e cea care ne privește direct: Eurostat publică datele prin SDMX și prin JSON-stat, iar Banca Mondială e unul dintre sponsorii SDMX.

08 · Cum arată o cerere

Mesajul HTTP

Tot ce face un API REST trece prin HTTP, iar HTTP e, la bază, un schimb de două mesaje text. Cererea și răspunsul au aceeași structură: o primă linie, un șir de antete de forma Nume: valoare, un rând gol și, opțional, corpul.

StructurăCererea din caietul 02, întreagă

Antetele care contează la colectare

AntetÎnCe spune
Acceptcererece formate acceptă clientul
User-Agentcererece program trimite cererea; unele API-uri cer o valoare descriptivă
Content-Typerăspunsformatul corpului; dacă nu e JSON, corpul nu se citește cu .json()
Retry-Afterrăspunscâte secunde trebuie așteptat după un refuz de tip 429 sau 503

REST e un stil arhitectural construit peste HTTP: resursele au adrese, operațiile folosesc metodele standard, iar serverul nu păstrează stare între cereri. Consecința practică pentru colectare: o cerere poate fi repetată oricând, de oriunde, cu același efect.

HTTPS e același HTTP, criptat. Versiunile HTTP/2 și HTTP/3 schimbă felul în care mesajele circulă (binar, multiplexat, peste QUIC la HTTP/3), nu înțelesul lor: metoda, adresa, antetele și codul de stare rămân aceleași.

Antetele cererii se pot vedea din Python cu raspuns.request.headers, iar cele ale răspunsului cu raspuns.headers.

09 · Cum arată o cerere

Metodele HTTP

Metoda e primul cuvânt din cerere și spune ce operație se cere asupra resursei. Cele patru operații de bază asupra unei colecții de date se numesc, pe scurt, CRUD (create, read, update, delete), iar HTTP le dă câte o metodă; modificarea are două: PUT înlocuiește resursa întreagă, PATCH doar câmpurile trimise.

SimulareCinci metode, o colecție de exemplu

Două proprietăți contează la colectare. O metodă e sigură dacă nu schimbă nimic pe server, și idempotentă dacă repetarea ei are același efect ca o singură execuție. GET le are pe amândouă, deci o colectare întreruptă se poate relua fără riscuri. PUT și DELETE sunt idempotente, deși schimbă ceva; POST nu e: două cereri identice creează două resurse.

12 · Cum arată o cerere

Structura unei adrese

O adresă pare un simplu șir de caractere, dar are o gramatică. Când o cerere eșuează, eroarea se află aproape întotdeauna într-una dintre componente, iar pentru a o găsi, componentele trebuie să poată fi numite.

ExplorareAdresa primei cereri din caietul 02

Calea identifică resursa, iar parametrii o filtrează. Un cod de indicator greșit în cale duce la o eroare sau la altă resursă; un an greșit în parametri duce la un răspuns gol sau la un mesaj de eroare în corp. Mai există o componentă, fragmentul de după #, care nu se trimite niciodată la server: rămâne în browser.

Codificarea (percent-encoding) înlocuiește caracterele care au alt rol în adresă: „:” devine %3A, spațiul devine %20 sau +. Cu params=, requests face codificarea; într-o adresă scrisă manual, codificarea trebuie făcută explicit.

Unde pui filtrele unei cereri, de exemplu anul sau formatul?

În parametri. Fragmentul, de după #, nu se trimite la server: rămâne în browser.

13 · Cum arată o cerere

Codurile de stare

Primul câmp al răspunsului e codul de stare, un număr de trei cifre. Prima cifră dă clasa: 2xx reușită, 3xx redirecționare, 4xx eroare a cererii, 5xx eroare a serverului. Codul se verifică înaintea corpului, pentru că la o eroare corpul poate fi o pagină HTML sau poate lipsi.

SimulareCinci situații tipice ale aceleiași cereri
CodCe înseamnăCe se face
200cererea a reușitse citește corpul și se verifică numărul de valori primite
301 / 302resursa s-a mutatrequests urmează automat redirecționarea
400cererea e greșităse verifică parametrii
401 / 403lipsește accesulcheie lipsă, greșită sau fără drepturi
404resursa nu existăse verifică calea
429prea multe cererise așteaptă (Retry-After) și se reia mai rar
500 / 503eroare la serverse reia mai târziu

La 429 și 503, un script de colectare reîncearcă automat, cu pauze care cresc după fiecare refuz (de exemplu 1, 2, 4, 8 secunde). Strategia se numește exponential backoff și protejează atât colectarea, cât și serverul.

Banca Mondială și codul 200

La un parametru invalid, API-ul Băncii Mondiale răspunde cu 200 și pune eroarea în corp, sub cheia message. După cod se verifică și structura răspunsului.

Răspunsul are codul 429. Ce înseamnă?

429 înseamnă depășirea limitei de cereri.

18 · requests

Paginarea

Un API nu trimite un set mare dintr-o dată. Trimite o pagină și, separat, informația de paginare: pagina curentă, numărul de pagini, câte valori pe pagină și câte în total. La Banca Mondială, informația aceasta e primul element al listei din răspuns.

ComparațiePopulația României, 1960 la 2024: 65 de valori

Sunt două strategii. Prima cere pagină după pagină, până la ultima; e singura posibilă când API-ul limitează per_page. A doua cere o pagină destul de mare încât să încapă totul și verifică apoi că a venit o singură pagină; caietul folosește a doua. Banca Mondială întoarce valorile de la anul cel mai recent spre cel mai vechi.

PredicțieCâte valori au venit
Pas cu pasUnde e a treia valoare

Scriptul complet, cu buclă

import time
import pandas as pd
import requests

def aduce(url, parametri):
    pagina, toate = 1, []
    while True:
        r = requests.get(url, params={**parametri, "page": pagina}, timeout=30)
        r.raise_for_status()
        meta, valori = r.json()
        toate.extend(valori or [])
        if pagina >= meta["pages"]:
            return toate
        pagina += 1
        time.sleep(0.5)

Din JSON în tabel

Lista de înregistrări devine tabel cu pd.json_normalize: dicționarele dinăuntru devin coloane cu punct în nume, de exemplu country.id. Eurostat oferă mai multe API-uri: Statistics API, care răspunde în JSON-stat și pe care îl folosim, și API-urile SDMX 2.1 și SDMX 3.0, pentru schimbul standardizat între instituții. Migrația, a doua sursă a proiectului

Setul migr_pop1ctz spune câți oameni cu o anumită cetățenie trăiesc într-o țară, la 1 ianuarie. Un rând e o pereche de țări, ca la SCI, dar cu direcție. Și cetățenia are o limită: persoanele care au dobândit cetățenia țării de reședință nu mai apar ca migranți.

Doar o parte dintre țări raportează pe țări de cetățenie; o valoare lipsă nu înseamnă zero. Harta din cursul 1 folosește exact aceste date: 1.073.196 de cetățeni români în Italia, la 1 ianuarie 2024. Aceasta este întrebarea empirică a semestrului: Italia, țara cu cei mai mulți cetățeni români, e abia a șasea după indicele SCI.

Prima colectare, în caiet

Colectarea se face în caietul 02, din dsw/curs/. Căile pornesc de acolo: data/c2/bm.csv înseamnă dsw/curs/data/c2/bm.csv. Folderul este creat de prima celulă a caietului, cu Path("data/c2").mkdir(exist_ok=True).

PasulCe faci
1deschizi caietul 02 din dsw/curs/, cu kernelul .venv
2rulezi secțiunile 1 la 5: prima cerere, paginarea, cei trei indicatori
3verifici că fiecare indicator a venit pe o singură pagină
4salvezi tabelul în data/c2/bm.csv

Mai jos, aceeași idee, scrisă complet, cu paginarea tratată pas cu pas: o funcție care cere pagină după pagină, până la ultima. Se poate rula într-o celulă nouă, la finalul caietului, și se adaptează la indicatorul echipei.

import time
import pandas as pd
import requests

URL = "https://api.worldbank.org/v2/country/RO/indicator/SP.POP.TOTL"

def aduce(url, parametri):
    pagina, toate = 1, []
    while True:
        r = requests.get(url, params={**parametri, "page": pagina}, timeout=30)
        print("pagina", pagina, "cod", r.status_code)
        r.raise_for_status()
        meta, valori = r.json()
        toate.extend(valori or [])
        if pagina >= meta["pages"]:
            return toate
        pagina += 1
        time.sleep(0.5)

randuri = aduce(URL, {"format": "json", "date": "2000:2023", "per_page": 100})
tabel = pd.json_normalize(randuri)
tabel.to_csv("data/c2/populatie_ro.csv", index=False)
print("salvate", len(tabel), "rânduri")

23 · Proiectul tău

Depozitul echipei, în dsw/proiect

Până acum, tot ce s-a lucrat se află în curs/, pe calculatorul personal, fără Git. Proiectul de semestru funcționează diferit: la el lucrează cinci persoane, iar fiecare trebuie să vadă ce au făcut ceilalți. De aceea fiecare echipă are un depozit al ei pe GitHub, în organizația dsw-ubb-2026, pornit din același șablon pentru toate echipele, iar fiecare membru îl clonează pe calculatorul propriu, în dsw/proiect.

  1. Echipa de cinci primește un depozit al ei, în organizația dsw-ubb-2026, pornit din același șablon pentru toate echipele.
  2. Accepți invitația de pe GitHub, primită pe e-mail, pentru dreptul de scriere în depozit.
  3. Copiezi adresa depozitului: pe pagina lui, Code → HTTPS.
  4. În terminalul din VS Code, în dsw:
    git clone <adresa> proiectultimul cuvânt e numele folderului: proiect
dsw/ ├── .venv/ ├── curs/ # al tău, fără Git └── proiect/ # al echipei, cu Git ├── .git/ # istoricul └── README.md

git clone copiază depozitul cu tot cu istoricul lui, în folderul .git/, și reține adresa de la care a fost copiat. Ultimul cuvânt din comandă e numele folderului: fără el, folderul ar purta numele depozitului. Comanda se dă o singură dată, din dsw; dacă e dată din alt folder, de exemplu din curs/, depozitul ajunge acolo, iar căile din caiete nu mai sunt cele din manual.

Git

Se instalează de pe git-scm.com; instalarea se verifică cu git --version. La prima clonare, Git poate cere autentificarea în contul GitHub, într-o fereastră din browser. Commit, push și lucrul pe ramuri, în proiect/, sunt la cursul 3.
