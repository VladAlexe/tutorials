Aceeași întrebare, patru stiluri

Populația României în 2024, cerută în fiecare stil.

REST

o resursă la o adresă; forma o decide serverul

GET /v2/country/RO/indicator/SP.POP.TOTL?date=2024

GraphQL

o interogare; forma o decide clientul

{ country(code: "RO") { population(year: 2024) } }

gRPC

o funcție la distanță; forma o fixează contractul

Populatie({tara: "RO", an: 2024})

SOAP

un mesaj XML; forma o fixează contractul

<Populatie><tara>RO</tara><an>2024</an></Populatie>

Doar exemplul REST este un API real, al Băncii Mondiale; celelalte arată forma aceleiași cereri.

ExercițiuCe metodă se folosește

Răspunsul începe cu un cod

Clasa codului arată unde e problema: în cerere (4xx) sau la server (5xx). Un 2xx înseamnă reușită, dar nu garantează date; corpul se verifică separat.

SimulareCinci situații tipice ale aceleiași cereri

Răspunsul are codul 429. Ce înseamnă?

429 înseamnă depășirea limitei de cereri. Se reia mai rar: după pauza din Retry-After, iar la colectări mari, cu pauze care cresc după fiecare refuz.

Aceeași cerere, în Python

Fiecare parte a mesajului HTTP are un nume în requests. Ordinea: cererea, codul de stare, abia apoi corpul.

În mesajul HTTPÎn Python, cu requests
cererea→raspuns = requests.get(url, params=parametri)
codul de stare→raspuns.status_code # 200
antetele→raspuns.headers # Content-Type: application/json
corpul→raspuns.json() # liste și dicționare
