01 · Recapitulare

Git, pe scurt: lucrul zilnic pe dev

Lecția 3 a introdus depozitul echipei și ramura dev. De aici încolo, Git devine un obicei de lucru, nu un subiect separat: fiecare pas al proiectului se încheie cu un commit pe dev. Tabelul rezumă ciclul zilnic și adaugă cele trei anulări de care este nevoie cel mai des.

CândComenzileCe fac
la începutul lucruluigit switch dev ; git pullramura de lucru, la zi cu colegii
după un pas încheiatgit add fisier ; git commit -m "mesaj"pasul intră în istoric
imediat dupăgit pull ; git pushîntâi ce au trimis colegii, apoi trimiterea proprie
o modificare greșită, înainte de addgit restore fisierfișierul revine la ultimul commit
un add greșitgit restore --staged fisierfișierul iese din pregătire; modificarea rămâne
un commit greșit, deja publicatgit revert <cod>un commit nou care îl anulează; istoricul colegilor rămâne intact

Cele trei anulări lucrează la niveluri diferite. git restore și git restore --staged lucrează la nivel de fișier, înainte de commit. git revert lucrează la nivel de commit și este singura variantă sigură după publicare, pentru că adaugă un commit nou în loc să rescrie istoricul pe care colegii l-au preluat deja.

Ai modificat din greșeală caietul echipei și încă nu ai dat git add. Cum revii la versiunea din ultimul commit?

git restore aduce fișierul la starea din ultimul commit. Varianta cu --staged doar îl scoate din pregătire, revert lucrează cu commit-uri, nu cu fișiere, iar git rm l-ar scoate din depozit.

Toate comenzile

02 · Cursul

Curățarea și integrarea datelor

Preprocesarea (C3) a adus sursele la o structură comună: coloanele necesare, denumiri consecvente, unitatea de analiză corectă. Curățarea pune o întrebare diferită: dacă valorile din această structură sunt corecte, complete și comparabile între surse. Integrarea unește apoi tabelele într-un tabel de analiză.

Etapele urmează o ordine stabilă, pentru că fiecare presupune rezultatele celei anterioare: profilarea precede orice decizie, codurile se aliniază înainte de unire, iar validarea încheie procesul. Tabelul leagă fiecare etapă de secțiunea caietului în care este aplicată.

Cât timp ocupă curățarea

O estimare citată frecvent (CrowdFlower, 2016) atribuie curățării și organizării datelor aproximativ 60% din timpul unui proiect. Cifra provine dintr-un sondaj comercial, nu dintr-un studiu riguros, și trebuie citită ca ordin de mărime: curățarea ocupă o parte importantă a muncii, iar deciziile luate acum determină validitatea tuturor rezultatelor ulterioare.

04 · Profilarea

Tipurile: numerele sunt numere?

Tipul unei coloane decide ce operații se pot face cu ea. În tabelul indicatorilor, valoare este float64 (număr cu zecimale, cu NaN pentru lipsuri), iar regiune și indicator sunt object, adică text.

Când printre numere apare un text, de exemplu :, cu care Eurostat marchează uneori o valoare indisponibilă, pandas citește toată coloana ca text, iar calculele nu mai funcționează. pd.to_numeric cu errors="coerce" transformă textul în numere, iar ce nu poate fi număr devine valoare lipsă:

exemplu = pd.Series(["12.5", ":", "7"])     # o coloană citită ca text
pd.to_numeric(exemplu, errors="coerce")      # 12.5, NaN, 7.0

info() arată o coloană de valori ca object, nu ca număr. Ce înseamnă?

Pandas a găsit cel puțin o valoare pe care nu o poate interpreta ca număr: : la Eurostat, o virgulă zecimală, un spațiu. O singură valoare de acest fel este suficientă pentru ca întreaga coloană să fie citită ca text; pd.to_numeric(..., errors="coerce") o transformă în valoare lipsă.

05 · Curățarea

Duplicatele: cheie repetată sau conținut dublat

Un tabel are o cheie: coloanele care identifică un rând. În tabelul indicatorilor, cheia este regiune + indicator. O cheie repetată înseamnă două rânduri pentru aceeași observație, iar orice medie sau sumă calculată ulterior o numără de două ori.

Există și o dublură pe care duplicated nu o detectează: aceeași informație scrisă în două rânduri cu chei diferite. În SCI, perechea RO11-ITC4 și perechea ITC4-RO11 au chei diferite, dar descriu aceeași legătură, cu aceeași valoare. Această dublură de conținut se rezolvă la integrare, păstrând o singură ordine a fiecărei perechi.

regiune_1regiune_2sci
RO11ITC49.760Nord-Vest, Lombardia
ITC4RO119.760aceeași legătură, în ordine inversă

06 · Curățarea

Valorile imposibile sau neobișnuite

Două categorii trebuie ținute separat. O valoare imposibilă încalcă o regulă logică: un procent peste 100, o populație negativă. Ea se corectează sau se elimină, iar decizia se notează. O valoare neobișnuită este doar departe de celelalte. Ea se verifică în sursă și, de cele mai multe ori, se păstrează: poate fi chiar fenomenul studiat.

VerificareaÎn caietRezultatul
rezumatul pe indicatorgroupby("indicator")["valoare"].describe()o populație minimă de 0
cele mai mici valoripopulatie.nsmallest(3, "valoare")NO0B, Svalbard
procentele(procente["valoare"] > 100).sum()0 valori peste 100

Populația minimă din tabel este 0, la regiunea NO0B. Ce se face cu acest rând?

NO0B este Svalbard, arhipelagul norvegian, iar Eurostat raportează efectiv 0. Valoarea este neobișnuită, dar nu greșită. Regula: o valoare neobișnuită se verifică în sursă; doar o valoare imposibilă (un procent de 140, o populație negativă) se corectează sau se elimină.

Valorile extreme statistice

Regulile statistice pentru valori extreme (de exemplu, pragul de 1,5 ori intervalul intercuartilic) țin de explorarea distribuțiilor, în C6. La curățare contează regulile logice formulate explicit.

07 · Lipsurile

Ce înseamnă „lipsă”

Pentru pandas, o valoare lipsă este NaN. Două consecințe practice decurg de aici. Prima ține de citire: pandas transformă automat în NaN nu doar celula goală, ci și câteva texte (NA, N/A, null). În datele noastre, NA este codul Namibiei, deci citirea implicită ar pierde 44 de rânduri fără niciun mesaj. De aceea codurile de țară se citesc întotdeauna cu keep_default_na=False.

Pas cu pasNamibia și valorile lipsă

A doua consecință ține de calcule: statisticile (media, suma pe o coloană) ignoră valorile lipsă, în timp ce operațiile între coloane le propagă.

PredicțieMedia și valorile lipsă

value_counts() ascunde implicit valorile lipsă; cu dropna=False le numără și pe ele. Pe zboruri, 418 dintre perechi nu au pasageri raportați.

zboruri["pasageri"].isna().value_counts(dropna=False)   # False 1087, True 418
08 · Lipsurile

Cât lipsește și unde

După ce știm ce înseamnă „lipsă”, măsurăm cât lipsește și unde. Două măsuri sunt suficiente: numărul valorilor lipsă pe coloană și proporția lor. A doua permite compararea coloanelor între ele.

Exercițiu de codLipsurile pe coloane

Întrebarea decisivă este însă de ce lipsesc valorile. Dacă lipsurile sunt puține și fără tipar, rândurile pot fi eliminate fără consecințe. Dacă au un tipar (anumite țări nu raportează un indicator), eliminarea lor schimbă compoziția datelor, iar completarea lor inventează valori. În acest caz, lipsa se păstrează și se documentează.

ExercițiuTratamentul potrivit fiecărui caz
Decizia noastră

Păstrăm toate cele 298 de regiuni, fără să completăm valorile lipsă, și alegem pentru fiecare analiză doar coloanele de care are nevoie. Regiunile fără PIB sunt din Elveția, Norvegia, Albania, Bosnia și Herțegovina, Kosovo și Islanda: o eliminare ar scoate din analiză tocmai aceste țări.

09 · Curățarea

Aceeași țară, alt cod

Când se combină două surse, aceeași țară poate avea coduri diferite. Eurostat folosește EL pentru Grecia și UK pentru Regatul Unit, iar SCI folosește codurile ISO, GR și GB. Pentru program sunt țări diferite, iar o unire pe coduri le pierde fără niciun mesaj de eroare. Corecția se face înainte de unire, cu un dicționar explicit.

10 · Integrarea

Din lung în lat: un rând pe regiune

Tabelul indicatorilor este în format lung: un rând pe regiune și indicator. Formatul este potrivit pentru colectare și pentru verificări (un indicator nou înseamnă doar rânduri noi), dar analiza regiunilor cere un rând pe regiune, cu câte o coloană pe indicator: formatul lat. pivot face trecerea.

Pas cu pasDin lung în lat

În caiet, tabelul lat se lipește apoi de lista celor 298 de regiuni din SCI, cu how="left", ca să rămână și regiunile fără date. Numărul de rânduri se verifică imediat: 298 înainte, 298 după.

11 · Integrarea

Unirea tabelelor, cu o singură regulă

Perechile de regiuni se obțin din SCI în doi pași. Întâi se rezolvă dublura de conținut: se păstrează perechea în care primul cod este mai mic alfabetic, ceea ce elimină și perechile unei regiuni cu ea însăși (298 × 297 / 2 = 44.253 de perechi). Apoi se lipesc atributele fiecărui capăt, de două ori: o dată cu sufixul _1, o dată cu _2.

12 · Integrarea

Migrația în forma SCI: două direcții, un rând

SCI este simetric: o singură valoare pe pereche de țări. Migrația are direcție. Pentru a le aduce în același tabel, cele două direcții se lipesc pe același rând, prin două uniri, câte una pentru fiecare sens, iar apoi se adună.

Pas cu pasRomânii din Italia și italienii din România

Înainte de unire se verifică acoperirea: nu toate țările raportează migranții pe cetățenii. O țară care nu raportează are valoare lipsă la toate perechile ei, iar perechile cu ea ar avea migrația incompletă. Caietul păstrează doar țările care raportează cel puțin 20 de cetățenii: 24 de țări, deci 276 de perechi.

Valoare lipsă plus număr dă valoare lipsă

Este comportamentul corect: o pereche cu o direcție necunoscută nu are un total cunoscut. Cu zero în locul valorii lipsă, perechea Polonia-Germania ar părea cunoscută, dar ar fi greșită.

13 · Validarea

Validarea finală

Validarea compară tabelele finale cu regulile lor. Fiecare tabel de analiză are o cheie (regiunea, perechea de regiuni, perechea de țări), care trebuie să fie unică, și o variabilă de explicat, SCI, care trebuie să fie completă. Numărul de rânduri trebuie să fie cel calculat: 298 de regiuni, 44.253 de perechi de regiuni, 276 de perechi de țări.

Exercițiu de codVerificările finale

Celula se păstrează în caiet și se rulează la fiecare refacere a curățării. Rolul ei nu este să găsească erori o singură dată, ci să semnaleze imediat când o modificare ulterioară schimbă datele.

14 · Validarea

Jurnalul deciziilor

Curățarea nu este o succesiune de operații tehnice, ci o succesiune de decizii: ce se păstrează, ce se elimină, ce se înlocuiește. Fiecare decizie schimbă datele pe care se sprijină analiza, deci trebuie scrisă, împreună cu motivul ei. În proiect, jurnalul stă în README.md.

Criteriul unui jurnal complet

Un coleg care nu a participat la discuțiile echipei trebuie să poată reface curățarea doar pe baza caietului și a jurnalului. Dacă are nevoie de explicații suplimentare, documentația este incompletă.
